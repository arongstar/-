# 연수 교안 만들고 배포하기

초등 교사 대상 디지털·AI 연수 교안 사이트(Astro 정적 사이트, GitHub Pages)에 교안을 추가·수정하고 배포하는 절차입니다.

- 사용자: 구천초등학교 교사(남교사). 연수 강사로 다니며 교안을 모읍니다.
- **답은 항상 한국어로**, 쉬운 말로 합니다. 사용자는 개발자가 아니에요. PR·브랜치 같은 말은 처음 나올 때 한 줄로 풀어 줍니다.
- 사이트: https://arongstar.github.io/-/ (저장소 `arongstar/-`, 공개)

## 0. 시작 전에 (브랜치 맞추기)

작업 브랜치는 세션이 정해 준 브랜치(시스템 안내의 `claude/...`)를 씁니다. 이전 PR이 머지되었으면 먼저 main을 따라잡습니다.

```bash
git fetch origin main && git merge --ff-only origin/main
```

강제 푸시(force push)는 하지 않습니다. `node_modules`가 없으면 `npm ci`.

## 1. 자료 모으기

교안은 **사실이 정확해야** 합니다. 기억에 기대지 말고 확인합니다.

- 사용자가 준 URL·파일·이전 세션·Notion·구글 드라이브(동기화된 내 컴퓨터 폴더 포함)를 먼저 읽습니다.
- 서비스 소개 교안이면 그 사이트를 직접 열어 메뉴 이름·기능·요금·연령 기준을 확인하고, 최신 소식을 검색합니다. 자바스크립트로 그리는 사이트는 Playwright로 열어 봅니다(프록시 필요: `chromium.launch({ proxy: { server: process.env.HTTPS_PROXY } })`). 막힌 호스트는 환경 도구로 허용을 요청합니다.
- 유튜브는 클라우드에서 막히는 경우가 많아요. 제목은 oEmbed로 얻고, 내용은 사용자에게 스크립트(자막)를 부탁합니다.
- 무엇을 만들지 애매하면(예: 어떤 앱·활동을 넣을지) **먼저 구성안을 보여 주고 검토받은 뒤** 만듭니다.

## 2. 교안 파일 쓰기

`src/content/lessons/<id>.md` — id는 영문 소문자·숫자·하이픈(예: `tpicks`, `apps-script-webapp`). 주소가 `/lessons/<id>/`가 됩니다. `_템플릿.md`와 기존 교안(`tpicks.md`, `ai-tamheom-webapp.md`)을 본보기로 삼습니다.

### 머리 정보

```yaml
---
title: 서비스명 — 한 줄 부제        # PDF 파일 이름은 ' — ' 앞부분 + " 교안.pdf"
cover: /images/covers/<id>.jpg     # 3번에서 만듦
summary: 목록 카드에 보일 1~2문장
date: 2026-11-16                   # 오늘 날짜 (최신이 목록 맨 앞)
audience: 초등 교사                # 예: 유·초등 교사, 초등 3~6학년 담임
duration: 90분                     # 예: 2시간, 2~3차시
tags: [주제1, 주제2]
materials:
  - title: 실습 활동지 (.docx)
    file: /files/<id>/파일이름.docx
    description: 무엇이 들어 있는지
  - title: 바로가기
    file: https://...
sites: [site-id, ...]              # src/data/sites.yaml 의 id
---
```

### 본문 구성 (이 순서가 기본)

1. `> 📌 **2026년 ○월 화면 기준**으로 정리했어요. …` — 화면이 바뀔 수 있다는 안내
2. `## 0. 오늘의 흐름` — 첫 칸이 `시간`인 표(진행표로 보임) + **준비물** + 💡 팁
3. `## 1. ○○는 무엇일까?` — 개념, 메뉴 표, 흐름 그림(SVG)
4. `## 2.` ~ — 기능별 설명 + `### ✋ 실습① 제목 (10분)` 실습 카드 + 예시 프롬프트
5. 마지막 쪽: `## N. 안전하게 쓰기`(개인정보·저작권·연령 기준·학생 사용 시 주의), 필요하면 `## 마무리` / 자주 묻는 질문

### 쓰는 기호 (`src/lib/remark-prompt-blocks.mjs`가 화면 요소로 바꿈)

| 쓰기 | 보이기 |
| --- | --- |
| ```` ```prompt 제목 ```` … ```` ``` ```` | [복사] [.txt 받기] 프롬프트 카드. 옆 상자에 목록·전체 받기 자동 |
| `> 💡 …` / `> ⚠ …` / `> 📌 …` | 도움말(초록) / 주의(노랑) / 안내(파랑) 상자 |
| `### ✋ 실습① …` | 다음 `###` 이상 제목 전까지 실습 카드. 안의 번호 목록은 단계 표시 |
| `📍 메뉴 › 하위 메뉴` (문단 맨 앞) | 메뉴 위치 칩 |
| 첫 머리칸이 `시간`인 표 | 진행표 |
| `![설명](/images/<id>/그림.svg)` | 그림 (경로는 `/`로 시작, 기본 경로는 자동으로 붙음) |

### 글쓰기 규칙

- 말투는 **해요체**, 짧은 문장. 선생님이 연수장에서 따라 하기 쉽게 메뉴 이름은 **굵게**.
- **굵게 바로 뒤에 조사를 붙이지 않습니다.** `**[수정하기]**에서`는 굵게가 안 돼요. → `**[수정하기]** 에서` 또는 `[**수정하기**]에서`처럼 닫는 `**` 앞에 문장부호가 오지 않게 씁니다.
- 물결표 `3~6학년`은 그대로 써도 됩니다(취소선 꺼 둠). 단 `~~두 개~~`는 취소선이 돼요.
- 프롬프트 예시는 **6학년 국어**처럼 구체적인 학년·교과·상황을 넣고, 학생 실명·개인정보는 넣지 않습니다.
- 다른 사람(동료 교사 등)의 이름은 **사용자에게 확인받기 전에는 넣지 않습니다.** 다른 사람이 만든 원본 자료(zip 등)는 원작자 동의 없이 올리지 않습니다.
- 강사 이름·소속은 본문에 쓰지 않습니다. `src/site.config.ts`의 `INSTRUCTOR`가 **PDF 표지에만** 자동으로 들어가요.

## 3. 사이트 모음 · 자료 · 그림

### 사이트 모음 (`src/data/sites.yaml`)

교안 `sites:`에 쓴 id가 없으면 추가합니다. `category`는 `src/site.config.ts`의 `CATEGORY_ORDER` 중에서 고르고, `use`는 `교사용` 또는 `학생 활동 가능`만 씁니다. 연령·약관 주의는 `note`에.

### 내려받기 자료 (`public/files/<id>/`)

- 활동지는 `.docx`(python-docx 또는 docx 스킬)로 만듭니다. 한글 파일 이름 그대로 씁니다(예: `티픽스_실습활동지.docx`).
- 프롬프트 모음은 화면에서 자동으로 .txt를 받을 수 있으니 따로 안 만들어도 됩니다.
- 구글 시트 양식은 사용자 드라이브에 올려 링크 공유(보기) 후 `…/copy` 주소(사본 만들기 링크)를 `materials`에 넣습니다.

### 그림

- **표지(`public/images/covers/<id>.jpg`)**: 사용자의 캐릭터(남교사 치비 캐릭터)로 그립니다. 옷·표정·동작만 바꿉니다. 방법은 [references/cover-image.md](references/cover-image.md). 캐릭터 시트: `assets/character-ref.jpg`.
- **설명 그림(흐름도·구조도)**: 글자가 들어가는 그림은 이미지 생성 대신 **SVG를 직접** 씁니다(`public/images/<id>/flow.svg` 등). 한글이 정확해야 하니까요. 밝은/어두운 화면 모두에서 보이게 배경색을 넣습니다.
- 서비스 화면 캡처는 Playwright로 찍을 수 있으면 넣고, 로그인이 필요한 화면은 사용자에게 부탁합니다.

## 4. 빌드하고 검사하기

```bash
BASE_PATH=/-/ npm run build
node .claude/skills/lesson-publish/scripts/check-site.mjs <id>
```

검사 스크립트가 취소선, 깨진 링크·그림·자료, 없는 사이트 id, 굵게가 안 된 곳, 공개 화면에 강사 이름이 나오는지 봅니다. 다른 사람 이름이 빠졌는지도 보려면 `--names 이름1,이름2`. 전부 통과(`✓ 문제 없음`)해야 다음으로 갑니다.

**PDF도 확인**합니다(강사비 제출용이라 중요해요):

```bash
LANG=C.UTF-8 PW_EXECUTABLE=$(ls -d /opt/pw-browsers/chromium-*/chrome-linux*/chrome | head -1) BASE_PATH=/-/ npm run build:pdf
```

`dist/pdf/<id>.pdf`를 열어(Read 도구, pages 지정) 표지·안내 쪽·본문이 넘치거나 잘리지 않았는지 봅니다. 화면도 Playwright로 PC 폭과 휴대폰 폭(390px)에서 한 번씩 찍어 확인합니다. 로컬 미리보기는 `dist`를 `-` 폴더로 복사해 `python3 -m http.server`로 띄우면 `/-/` 경로가 맞습니다.

## 5. 커밋 → PR → 머지 → 배포 확인

1. 커밋 메시지는 한국어로 무엇을 했는지(예: `티픽스 교안 추가`). 세션이 알려 준 작업 브랜치로 `git push -u origin <브랜치>`.
2. GitHub MCP로 PR을 만듭니다(제목·본문 한국어: 무엇을 넣었는지, 확인한 것, 남은 일).
3. **머지는 사용자가 "머지해줘"라고 할 때만** 합니다. `merge_pull_request`에 `expectedHeadSha`(40자 전체)를 넣습니다. 사용자가 조건을 달면("○○ 빼고 머지해줘") 먼저 고치고 PR 본문도 고친 뒤 머지합니다.
4. 머지하면 main에서 배포 작업이 돕니다. `actions_list`(`list_workflow_runs`)로 결과를 확인합니다(보통 1~2분). 실패하면 `get_job_logs`로 원인을 찾아 고칩니다.
5. 사용자에게 보고: 교안 주소 `https://arongstar.github.io/-/lessons/<id>/`, PDF는 교안 위쪽 **📄 교안 PDF 받기** 버튼, 예전 화면이 보이면 Ctrl+F5. 확인하지 못한 것(실서버 테스트 못 함 등)은 숨기지 말고 말합니다.

## 마무리 보고에 넣을 것

- 무엇을 만들었는지(실습 몇 개, 프롬프트 몇 개, 자료, 새 사이트)
- 확인한 것과 **확인 못 한 것**
- 사용자가 직접 해야 하는 일(로그인 필요한 캡처, 자기 PC에서 실행할 명령 등)
- PR 링크 — 그리고 "괜찮으면 '머지해줘'라고 말씀해 주세요"
